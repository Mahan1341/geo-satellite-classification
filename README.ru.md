# Geo Satellites: ансамбль четырёх моделей для классификации изображений

Решение [соревнования Week 5](https://www.kaggle.com/competitions/week-5-competition-geo-satellites-classification) по курсу «Введение в машинное обучение» Университета Иннополис: классификация спутниковых изображений на 20 классов. Итоговая модель объединяет две ResNet101, InceptionV3 и VGG16-BN с ImageNet-предобучением, EMA и усреднением предсказаний по поворотам изображения.

**В исходных записях экспериментов указан public accuracy 0,96230** для тех же весов ансамбля, которые используются здесь. Это сохранённый исторический результат: при подготовке репозитория он не воспроизводился и не сверялся с итоговым лидербордом. Подтверждённых финальных private score и места здесь нет.

## Модель

| Компонента | Архитектура | Seed | Размер | Эпохи | Повороты при инференсе | Вес |
|---|---|---:|---:|---:|---|---:|
| R42 | ResNet101 | 42 | 256×256 | 15 | 0°, 180° | 0,153 |
| R1337 | ResNet101 | 1337 | 256×256 | 15 | 0°, 90°, 180°, 270° | 0,357 |
| INC | InceptionV3 | 42 | 299×299 | 15 | 0°, 90°, 180°, 270° | 0,340 |
| VGG | VGG16-BN | 42 | 256×256 | 9 | 0° | 0,150 |

ResNet101 использует веса torchvision ImageNet-1K V2; Inception и VGG — V1. Классификационные головы заменены под 20 классов, у VGG также используется global average pooling и компактная линейная голова.

Обучение использует AdamW, отдельные learning rate для backbone и головы, warmup с cosine decay, label smoothing, MixUp/CutMix и EMA с коэффициентом 0,999. ResNet и Inception проходят 12 эпох с mixing и 3 без mixing; VGG — 9 эпох с mixing, microbatch 6 и накоплением градиента на 3 шагах.

Обучение распараллелено между двумя GPU: на первой последовательно обучаются R42 и R1337, на второй — Inception и VGG. При инференсе каждая модель усредняет вероятности по указанным поворотам. Затем вероятности четырёх моделей складываются с фиксированными весами, класс выбирается через `argmax`. Отражения в финальном TTA не используются.

## Данные и смысл итогового запуска

Код ожидает исходные размеры соревнования: **4999 train, 699 validation и 8299 test изображений**. CSV-файлы называются `train.csv`, `val.csv`, `test.csv`; изображения лежат в каталогах `train/`, `val/`, `test/`. Колонка `id` совпадает с именем файла изображения, `label` содержит классы 0–19. Нужен также `sample_submission.csv` либо `sample_submission_example.csv` с тем же порядком ID, что в `test.csv`.

**Это финальное переобучение на всех 5698 размеченных изображениях.** Train и validation объединяются после выбора конфигурации. В этом ноутбуке нет повторного поиска гиперпараметров или независимой оценки на validation. Печатаемый во время обучения `top1`, особенно на смешанных батчах, не является validation accuracy.

Исторический public score взят из вводной ячейки `week5_FINAL4_R42_R1337_INC_VGG_GRID.ipynb` от 10 октября 2026 года: там явно записаны 0,96230 и веса 0,153/0,357/0,340/0,150. В финальных ноутбуках нет сохранённых outputs. Связь повторного запуска опубликованного кода с конкретным отправленным CSV отдельно не проверена. Подробности указаны в [recorded_results.json](reports/recorded_results.json).

## Запуск

Основной вариант — загрузить `solution.ipynb` в Kaggle, прикрепить данные соревнования, выбрать **GPU T4 ×2** и запустить все ячейки. Internet нужен для получения ImageNet-весов, если их нет в кэше. Выходной файл — `final_submission.csv`.

Исходный поиск данных проверяет текущий каталог, `../input` и непосредственно вложенные каталоги. Если данные лежат глубже, нужно настроить поиск корня данных или использовать вариант с замерами ниже.

В Linux с двумя CUDA GPU можно запустить тот же код как скрипт из корня репозитория:

```bash
python -m pip install -r requirements.txt
python solution.py
```

Данные должны находиться в корне репозитория или непосредственно вложенном каталоге. Нужна CUDA-сборка PyTorch, совместимая с драйвером, и соответствующая версия torchvision. В исходном финальном файле версии пакетов не записаны, поэтому `requirements.txt` содержит зависимости, а не вымышленную фиксацию прежнего окружения.

### Отдельный ноутбук для замеров

[notebooks/timed_retrain.ipynb](notebooks/timed_retrain.ipynb) — более поздний вариант той же модели с подробными замерами. Он ищет данные рекурсивно, при необходимости скачивает их через `kagglehub`, а после выполнения сохраняет отчёты о времени. Для скачивания требуется доступ к соревнованию в Kaggle. В ноутбуке нет вымышленных outputs.

В исходном коде оставлены проверки: инференс ≤120 секунд, обучение вместе с инференсом ≤45 минут. **Наличие проверок не подтверждает выполнение лимитов.** Исходный суммарный таймер исключает первоначальную загрузку данных и pretrained weights; вариант с замерами дополнительно считает время всего ноутбука.

## Ограничения и происхождение

- Реализация требует две CUDA GPU. На одной видеокарте она не запускается без изменений.
- Полный GPU-запуск при подготовке репозитория не повторялся. Seed зафиксированы, но параллельное выполнение и `cudnn.benchmark=True` не гарантируют побитовую воспроизводимость.
- Обученные состояния моделей остаются в памяти; checkpoints на диск не записываются. После перезапуска ядра потребуется новое обучение.
- Данные соревнования, CSV с предсказаниями и веса моделей в репозиторий не включены.

Это командный учебный проект **CHIMIN PRIME**, сохранённый в портфолио Владимира Гаранина. В работе и подготовке репозитория использовалась помощь ИИ. Основной код взят из `final_solution.ipynb`; единственное исполняемое изменение — добавленный импорт `Subset` для ветки загрузки небольшого подмножества test. При оформлении добавлены документация, заголовки ячеек, экспорт скрипта и очистка метаданных. [provenance.json](reports/provenance.json) фиксирует исходники и объём изменений.
